# 五子棋底片引擎 · 思考可视化

一个从"为什么"开始写起的五子棋 AI。所有对弈引擎都是**确定性**的纯 Python
实现(仅标准库),每一步棋的思考过程(底片轮廓、候选采纳概率、推理层)都会
实时画在棋盘上 —— 这不是黑箱引擎,是"看得见在想什么"的引擎。

```bash
# 依赖:Python 3.10+ 自带 tkinter,无任何第三方库
python vizplay/vizplay.py
```

打开后默认是**观战模式**:黑方"底片引擎·冠军版"对白方"底片引擎·经典版",
每点一次『走一步』看一方行棋及它的思考可视化;点『人执黑/人执白』即可亲自
对弈。**棋局结束会弹出提示,一键再来一局。**

## 研制思路

### 1. 起点:不做"棋形模板 + 启发式权重"

传统五子棋程序把"活三、冲四、双三"当硬编码棋形打分。问题:模板是写不完的,
权重是拍脑袋的,而且**说不清为什么这么走**。我们希望引擎的每一步都来自一条
可解释的推理链,并且所有"经验"都由训练数据决定,而不是人手调参。

### 2. 底片:从"保证能赢"倒推出来的威胁单元

先问一个严格的问题:在一个一维窗口(长 9)里,给定已有棋子,对方任意防守,
我方**保证**几步成五?答案由一个局部的 AND/OR 逆向求解给出(`retrograde.py`,
19683 个局势,0.03 秒解完)。由此涌现出:

- k=0 五连、k=1 冲四/活四、k=2 活三 —— **经典棋形不是定义的,是解出来的**;
- 一维语言保证天花板 k≤2 —— 更深的威胁必须看多条线的交点组合(双三/四三等)。

**底片(Film)** 就是一次逆向求解的产物:已有子 + 必空轨迹 + 倒计时 k。
棋盘语言(`language.py`)把所有一维结构按 D4 对称折叠,同一形状无论朝向、
翻面都归一 —— 这是后面一切"对称学习"的地基。

### 3. 引擎的分级:必胜 > 不输 > 可能赢

`agent.py` 的分层思想保留到所有版本:
1. 必赢层(一手成五 / 融合 ≤2 / 强制链 VCT)直接走;
2. 不输层(对方单线保证、反四链)过滤,只留合法候选;
3. 可能赢层:对收敛后的候选评分取最高。

`vct.py` 把威胁空间搜索完备化(AND/OR + 杀死格 + 竞速 + Zobrist 转置),
保证预算内的强制胜不被漏掉 —— 深推理只花在真正需要的地方。

### 4. M2:区域剪枝把算力集中在关键处

棋盘 225 格,不可能每格都深想。`rl_agent.py` 用**区域剪枝**:学到的关系特征
给区域打分,只保留与最优分差阈值内的区域,候选自然收敛;再对聚焦域做受限
VCT 深推理,最后按特征权重评分(点级 19 + 区域关系 33)。权重不是手调的,
而是 `distill.py` 从 Rapfi(外部冠军引擎)对局数据蒸馏出来 —— 用冠军的落点
当标签,线性 softmax 拟合。

### 5. 记忆:可加的槽族,而不是调死一个权重

单一权重永远有盲区。设计改为**槽族**:细落子指纹槽(`filmsig.py`,D4 折叠后
同一形状只占一个键)、几何关系槽、层级槽。每个槽的权重初始为零(中立),
出现一次证据就加一点。训练 = 在槽上积累,而不是重写整个评分函数。

经典版(曾胜网页版)就是这样训练出来的:在线教学回路里,测试版与对手
(网页版引擎)打整局,只有**冠军也赢**的证据才更新槽,7 帧一致性 ≥5/7 才采纳,
落盘原子写 + 备份。最终固定为 20 个槽的 RL1.0 最强版 —— 它真的在网页版
对手上赢过,所以叫"曾胜网页版"。

### 6. RL 2.0(v3.3):让引擎"推理"而不是"打分"

冠军版的关键改动:候选评分不再只是特征加权,而是跑一个**两层注意力推理**:

- **底片层展开**:每层 = 下一批注意力底片,评分为三视图各自一层分;
- **逆向末端前推**:一个底片逆推两个前驱底片(双威胁雏形),棋子越少的
  末端前推分配越多算力 —— 少子时推得更深;
- **重复集合 → 解方程**:同一集合出现两次不再重展,做固定点迭代求节点值
  并回代父节点(节点值 = 先验 + 三层分 + 孩子均值);
- **三视图**:每层集分 我方推进 / 敌方威胁 / 敌我重合 三种视图,参数独立;
- **相对坐标**:任意两底片距离折叠成两轴规范码 (a≤b,每轴 ≤5),超距 → far;
- 每层评分 = 集合键分 gs + 深度分 depth + 层胜比 × 层权 ratio;
  候选格总分 = 基座 + 它落入的各层(depth≤3)分数之和。

### 7. 黑棋的困境:书是查出来的,不是想出来的

冠军版执黑最初打不过经典版白。逐手诊断(把每一步和冠军 Rapfi 的胜线 451
对比)发现:分歧发生在**第 2 手** —— 黑棋开局书里预定 (6,7),而冠军走 (6,9)。
差这一格,后面全盘皆输。

为什么不能靠训练修?因为书是"短路":命中书就直接落子,**根本不进评分层**,
所有 gs/geo/depth 槽都碰不到它(十轮搜索 0 补丁的实证)。写死一条线的书
换一个方向就失效 —— 这是查表的固有缺陷。

### 8. 解法:把"书"变成学出来的策略 —— 冠军模仿开局表

关键洞察:**前 4 手棋子极少,空间小到可以穷举**;而且只需要以第一手为原点,
利用旋转/镜像对称折叠,训练空间立刻缩小一个数量级:

- 以黑 1 为原点,限制 |dx|,|dy| ≤ 3(折叠后落在第一象限 4×4 域内);
- 白 1 的全空间折叠成 **9 个等价类**,黑 2 的全部应对折叠成 297 个代表局面
  (`opening_space.py` 枚举);
- **训练 = 直接摆好局面,问冠军(Rapfi)下一步怎么下**(监督模仿,而非
  整局胜率 rollout —— rollout 又贵又噪;模仿直接、便宜、可解释);
- 对手参数固定 = RL1.0 最强(黑白测试同一规则);只沿实际会出现的线延伸,
  "我们不走的动作不会出现"的分支天然不训;
- 黑白对称:黑侧学"任意白 1 → 冠军黑 2/3/4",白侧学"任意黑 2 → 冠军白 2/3";
- 表键 = 折叠后的局面指纹(带颜色),冠军着存规范坐标,查询时按当前局面
  的对称逆变换还原 —— 任何方向的同类局面都命中同一条(旋转对称已验证:
  白 1 四方向 → 黑 2 正确映射);
- **域外回退**:任何一手超出 4×4 域(包括对手故意贴边),表不覆盖 →
  引擎切换回正常思考(临时思考),绝不硬套。

训练产物 `external/opening_book_black.json`(27 条)/ `opening_book_white.json`
(81 条),推理端 `vizplay/opening_book.py` 在每次走子前查表。

**实测**:冠军版执黑 vs 经典版白 **3-0**(29 手 ×3,确定性引擎三次同线);
黑第 2 手 (6,9) 与冠军胜线 451 完全一致,黑 2/3/4 连续走表。

一个反直觉的教训:用 **5 秒**思考的冠军训表反而 0-3 输,用 **1 秒** 的
Rapfi400 同款训表 3-0 赢 —— 表越深越要和后续引擎风格匹配,深算的"更优"
一手接不住自己的后续。这也说明:开局表只是把引擎送进它熟悉的战场,
不是替它下完。

### 9. 可视化:让推理过程可见

`vizplay/` 是独立的思考可视化程序:

- 每个候选格画出**考虑底片**(底片 = 威胁单元)的轮廓:实心 = 活底片,
  空心 = 潜在底片,颜色深浅 = 该底片被最终采纳的概率(候选 softmax 映射);
- v3.3 引擎额外画出**推理层集**:蓝/红/紫 = 我方/敌方/重合三视图,深浅 = 层值;
- 右侧面板列出候选格采纳概率、考虑底片清单与三视图层统计;
- 棋盘米黄木纹,棋子黑白分明,最后一手橙色标记;窗口任意拉伸,棋盘等比缩放。

### 10. 局限与后续

- 开局表只覆盖 4×4 域内前 4 手;域外回到模型自身 —— 覆盖更广的开局库、
  或把开局先验直接训练进评分层(让"会走 (6,9)"是长出来的,不是查到的),
  是下一步;
- 引擎确定性 → 单局高方差,结论需要多开局 A/B(本仓结论均按固定对手复测);
- 对手参数固定是训练纪律:换对手需重新验证,不能假设通用。
